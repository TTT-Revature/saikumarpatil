## 5. PEP 8 and Naming Conventions 

### What is PEP 8?
**PEP 8** is the official **style guide for Python code**. A PEP (Python Enhancement Proposal) is a numbered document that describes a Python standard. PEP 8 says how code should look, so that all Python code is easy to read across teams and projects.

Real-life comparison: **traffic rules**. Everyone drives on the same side of the road and follows the same signals, so the whole city moves smoothly. PEP 8 is the traffic rules for Python code.

### Naming conventions

- **Variables and functions**: `snake_case` (lowercase with underscores)
  ```python
  student_name = "Asha"
  def calculate_total(): ...
  ```
- **Classes**: `PascalCase` (each word capitalised, no underscores)
  ```python
  class BankAccount: ...
  ```
- **Constants**: `UPPER_CASE_WITH_UNDERSCORES`
  ```python
  MAX_RETRIES = 3
  TAX_RATE = 0.18
  ```
- **Private/internal names**: start with one underscore
  ```python
  _cache = {}
  ```
- **Modules**: short, lowercase names, with underscores if needed (`payment_utils.py`)

### Layout rules
- Use **4 spaces** per indentation level. Never mix tabs and spaces.
- Keep lines to about **79 characters** (many teams use 88 or 100 instead).
- Put **two blank lines** before top-level functions and classes, and one blank line between methods inside a class.
- Put spaces around `=` in assignments, but **not** in keyword arguments:
  ```python
  x = 10                # good
  greet(name="Asha")    # good
  greet(name = "Asha")  # works, but against PEP 8
  ```
- Don't put spaces just inside brackets: `spam(ham[1], {eggs: 2})`.

### Imports
- Put imports at the **top** of the file.
- Group them in this order: standard library, third-party packages, your own modules. Leave a blank line between groups.
  ```python
  import os
  from datetime import date

  import requests

  from shop.billing import calculate_total
  ```
- Avoid `from module import *` (Module 5).

### Comments and docstrings
- Comments explain **why**, not what. Start them with `# ` and a space.
- Write a docstring for every public module, function, class and method.

### Tools that check PEP 8 automatically
- **flake8**: reports style problems
- **black**: formats code automatically to a consistent style
- **pylint**: checks style and possible bugs

```bash
python -m pip install flake8 black
python -m flake8 shop/
python -m black shop/
```

### Real-time example: before and after
Before (hard to read):
```python
def CalcTotal(Items,tax):
   t=0
   for I in Items:
     t=t+I*(1+tax)
   return t
```

After (PEP 8 style):
```python
def calculate_total(items, tax_rate):
    """Return the total price of items including tax."""
    total = 0
    for item in items:
        total += item * (1 + tax_rate)
    return total
```

> **Trainer tip:** Students should not memorise every PEP 8 rule. Ask them to run `black` on their code before every commit. The tool does the work for them.
