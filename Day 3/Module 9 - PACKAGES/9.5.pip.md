## 5. `pip` and Package Installation

### What is pip?
`pip` is the **package installer for Python**. It downloads libraries from the Python Package Index (PyPI) and installs them into the active environment.

Real-life comparison: an **app store** on your phone. You search for an app, tap install, and it is downloaded and set up for you.

### Common pip commands
```bash
python -m pip install requests           # install a package
python -m pip install requests==2.31.0   # install a specific version
python -m pip install --upgrade requests # upgrade to the latest version
python -m pip uninstall requests         # remove a package
python -m pip show requests              # show details of an installed package
python -m pip list                       # list everything installed here
```

> **Why `python -m pip` instead of just `pip`?** It guarantees that pip runs with the **same Python** you are using. This avoids the classic problem where a package is installed into one Python but the code runs in another.

### Installing several packages at once
```bash
python -m pip install requests pandas numpy
```

### Searching and checking versions
```bash
python -m pip index versions requests
```
This shows which versions are available.

### Installing from a file
```bash
python -m pip install -r requirements.txt
```
We cover this file in the next section.

### Real-time example: installing a package and using it
```bash
python -m pip install requests
```
```python
import requests

response = requests.get("https://api.github.com")
print(response.status_code)     # 200 means the request worked
```

### Common problems and fixes
- `ModuleNotFoundError: No module named 'requests'`: you installed into a different Python. Check that the environment is active, then reinstall with `python -m pip install requests`.
- `pip` is not recognised: use `python -m pip` instead, which works on every system.
- Permission errors: you probably forgot to activate `venv`. Installing into the global Python without permission is not a good habit.
