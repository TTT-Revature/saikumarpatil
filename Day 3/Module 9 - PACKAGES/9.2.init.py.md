## 2. `__init__.py`

### What does it do?
The `__init__.py` file marks a folder as a **regular package**, so Python knows it can be imported. It can be **empty**, and that is perfectly fine.

Real-life example: the **reception desk** at the front of an office building. It tells visitors that this building is an official office, and it can also give directions to the right floor.

### An empty `__init__.py`
Often this file is completely empty. Its presence alone is what matters.

### Using `__init__.py` to make imports simpler
You can import useful names into the package's `__init__.py`, so users don't need to know the inner file names.

```python
# shop/__init__.py
from .billing import calculate_total
from .inventory import check_stock
```

Now a user can write:
```python
from shop import calculate_total, check_stock
```
instead of:
```python
from shop.billing import calculate_total
from shop.inventory import check_stock
```

### Defining the public interface with `__all__`
`__all__` is a list in `__init__.py` that says which names are part of the public interface, which matters for `from shop import *`.

```python
# shop/__init__.py
__all__ = ["calculate_total", "check_stock"]
```

### Running code when a package is imported
Code placed in `__init__.py` runs when the package is first imported. Keep it light, such as simple imports and setup constants.

### Common mistake
Forgetting `__init__.py` in an older project may still work in modern Python (namespace packages), but it causes confusion and breaks some tools. Always include it.

### Real-time example: a clean public API
```python
# calculator/__init__.py
from .basic import add, subtract
from .advanced import power

__all__ = ["add", "subtract", "power"]
```
```python
from calculator import add, power

print(add(2, 3))       # 5
print(power(2, 5))     # 32
```
The internal file names (`basic`, `advanced`) can change later without breaking users.
