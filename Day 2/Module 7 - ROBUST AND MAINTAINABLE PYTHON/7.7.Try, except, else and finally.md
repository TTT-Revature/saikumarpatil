## 7. `try`, `except`, `else` and `finally` 

### Why handle errors?
Without error handling, one wrong input crashes the whole program.

```python
age = int(input("Enter your age: "))     # user types "abc" → ValueError, program stops
```

Real-life example: a **safety net** under a trapeze artist. If something goes wrong, the net catches the performer, and the show can go on in a controlled way.

### The basic structure
```python
try:
    # code that might cause an error
except SomeError:
    # what to do if that error happens
```

```python
try:
    age = int(input("Enter your age: "))
    print("Next year you will be", age + 1)
except ValueError:
    print("Please enter a valid number")
```

### Catching several errors
```python
try:
    a = int(input("First number: "))
    b = int(input("Second number: "))
    print("Result:", a / b)
except ValueError:
    print("Please enter whole numbers only")
except ZeroDivisionError:
    print("You cannot divide by zero")
```

### Getting the error message
```python
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print("Error:", e)              # Error: division by zero
```

### `else`: runs only if NO error happened
```python
try:
    number = int(input("Enter a number: "))
except ValueError:
    print("That was not a number")
else:
    print("You entered", number)
```

### `finally`: runs ALWAYS
The `finally` block runs whether an error happened or not. It is used for cleanup, such as closing files or connections.

```python
try:
    f = open("data.txt", encoding="utf-8")
    print(f.read())
except FileNotFoundError:
    print("File not found")
finally:
    print("Program finished checking the file")
```

Even with `with open(...)`, `finally` is useful for other kinds of cleanup, such as releasing a database connection.

### The full picture
```python
try:
    # 1. try this
    value = int(input("Enter a number: "))
except ValueError:
    # 2. runs ONLY if there was a ValueError
    print("Invalid input")
else:
    # 3. runs ONLY if there was no error
    print("Double is", value * 2)
finally:
    # 4. runs ALWAYS at the end
    print("Done")
```

### Catching everything (use carefully)
```python
try:
    risky_work()
except Exception as e:
    print("Something went wrong:", e)
```
`Exception` catches almost all errors. It is useful for logging, but avoid writing an empty `except:` with no error type, because it also hides serious problems like `KeyboardInterrupt`.

### Real-time example: a safe calculator
```python
def safe_divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        print("Cannot divide by zero, returning 0")
        return 0
    finally:
        print("Division attempted")

print(safe_divide(10, 2))
print(safe_divide(5, 0))
```

### Real-time example: a robust input loop
```python
while True:
    try:
        marks = int(input("Enter marks (0-100): "))
        if 0 <= marks <= 100:
            break
        print("Marks must be between 0 and 100")
    except ValueError:
        print("Please type a whole number")

print("Marks saved:", marks)
```
