## 4. Generator Expressions

### Same idea as list comprehensions, but lazy
A **generator expression** looks like a list comprehension, but it uses **round brackets**. It produces values one at a time, instead of building the whole list.

```python
squares_list = [n * n for n in range(5)]    # list comprehension → [0, 1, 4, 9, 16]
squares_gen = (n * n for n in range(5))     # generator expression → generator object

print(squares_gen)                          # <generator object ...>
print(next(squares_gen))                    # 0
print(next(squares_gen))                    # 1
```

> **Careful:** `(x for x in ...)` gives a generator, not a tuple. For a tuple, use `tuple(x for x in ...)`.

### Using generator expressions with functions
Functions like `sum()`, `max()`, `min()`, `any()` and `all()` accept generators directly, which saves memory.

```python
total = sum(n * n for n in range(1, 1_000_001))
print(total)

print(any(word.startswith("a") for word in ["cat", "ant", "dog"]))   # True
print(all(m >= 40 for m in [45, 60, 72]))                             # True
```

### Real-time example: total size of many files
```python
from pathlib import Path

total_bytes = sum(f.stat().st_size for f in Path(".").glob("*.txt"))
print(f"Total size: {total_bytes} bytes")
```

### Quick decision guide
- Need the values **many times** or need **indexing** (`x[3]`)? → use a **list**.
- Need the values **once**, one at a time, to save memory? → use a **generator**.

### Generator function vs generator expression
- **Generator expression:** one line, simple logic, like `(x * 2 for x in data)`.
- **Generator function:** several lines, with `yield`, for complicated logic.
