## 2. `iter()`, `next()` and `StopIteration` 

### `iter()`: get an iterator from an iterable
```python
colors = ("red", "green", "blue")
it = iter(colors)
print(it)                    # <tuple_iterator object at ...>
```

### `next()`: get the next item
Each call to `next()` returns the next item and moves the bookmark forward.
```python
colors = ("red", "green", "blue")
it = iter(colors)

print(next(it))     # red
print(next(it))     # green
print(next(it))     # blue
```

### `StopIteration`: what happens at the end
When there are no more items, `next()` raises a **`StopIteration`** exception. This is Python's way of saying "the bookmark has reached the end".
```python
print(next(it))     # StopIteration
```

Normally you never see this error, because a `for` loop catches it for you and stops quietly. A `for` loop is really doing this behind the scenes:

```python
nums = [10, 20, 30]
it = iter(nums)

while True:
    try:
        value = next(it)
    except StopIteration:
        break
    print(value)
```
```
10
20
30
```

### Giving a default value with `next()`
Add a second argument to avoid the error:
```python
it = iter([1, 2])
print(next(it))              # 1
print(next(it))              # 2
print(next(it, "No more"))   # No more
```

### Real-time example: reading a list of tasks one at a time
```python
tasks = iter(["Check email", "Write report", "Team call"])

current = next(tasks, None)
while current is not None:
    print("Working on:", current)
    current = next(tasks, None)
```

> **Trainer tip:** Show students that an iterator can be used **only once**. After it reaches the end, it stays empty. A list can be looped over again, but an iterator cannot.
> ```python
> it = iter([1, 2])
> print(list(it))     # [1, 2]
> print(list(it))     # []   ← already used up
> ```
