### Why does this module matter?
Writing code that works once is easy. Writing code that **keeps working** when users type wrong input, files go missing, data is large, and a teammate has to change it next year is the real skill. This module covers the tools that make Python code **robust** (it doesn't crash easily), **efficient** (it handles large data smoothly) and **maintainable** (others can read, fix and extend it).

## 1. Iterable vs Iterator 

### Iterable: something you can loop over
An **iterable** is any object that can be looped over with `for`. Lists, strings, tuples, sets, dictionaries and ranges are all iterables.

Real-life example: a **book**. You can read it page by page, but the book itself is not "reading in progress". It is something you *can* read.

```python
fruits = ["apple", "banana", "mango"]    # iterable
for fruit in fruits:
    print(fruit)
```

### Iterator: something that remembers where it is
An **iterator** is an object that gives you **one item at a time** and remembers its position. It produces the next item when asked, and it runs out when there are no more items.

Real-life example: a **bookmark** placed in a book. The bookmark knows which page you are on. Each time you turn a page, the bookmark moves forward. When you reach the last page, there is nothing more to read.

### The key difference
- An **iterable** can *give you* an iterator.
- An **iterator** *is* the thing that moves forward one step at a time.

```python
fruits = ["apple", "banana", "mango"]   # iterable
it = iter(fruits)                        # iterator (the bookmark)
```

### Checking the difference
```python
print(hasattr(fruits, "__iter__"))      # True  (iterable)
print(hasattr(fruits, "__next__"))      # False (not an iterator)

print(hasattr(it, "__iter__"))          # True
print(hasattr(it, "__next__"))          # True  (iterator)
```

### Why this matters
A list is **not** an iterator. If you try to call `next()` on a list directly, Python complains:
```python
nums = [1, 2, 3]
next(nums)     # TypeError: 'list' object is not an iterator
```

Use `iter()` first:
```python
nums = [1, 2, 3]
it = iter(nums)
print(next(it))     # 1
```

### Real-time example: a file is also an iterator
When you loop over a file line by line, the file object is an iterator that reads one line at a time. A huge file with millions of lines never has to fit into memory at once.
```python
with open("big_file.txt", encoding="utf-8") as f:
    for line in f:          # reads one line at a time
        print(line.strip())
```
