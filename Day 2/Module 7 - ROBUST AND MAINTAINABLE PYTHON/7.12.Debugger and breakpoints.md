## 12. Debugger and Breakpoints

### What is a debugger?
A **debugger** lets you pause a program in the middle of running, look at all the variable values, and move forward one line at a time. Instead of guessing, you can **watch** the program.

Real-life example: a **car mechanic** who doesn't just listen to the engine. They open the bonnet, pause the engine, check each part, and run it slowly to see exactly where the problem starts.

### Breakpoints
A **breakpoint** tells the program: "stop here, before running this line".

Two ways to set a breakpoint:

**1. In your code editor (VS Code, PyCharm)**
Click in the left margin next to a line number. A red dot appears. Press the **Debug** button to run the program, and it pauses at that line.

**2. In your code, using `breakpoint()`** (Python 3.7+)
```python
def calculate_total(prices):
    total = 0
    for p in prices:
        breakpoint()          # the program pauses here
        total += p
    return total

print(calculate_total([100, 250, 50]))
```
When the program reaches `breakpoint()`, it opens the Python debugger in the terminal.

### Common debugger commands (pdb)
When you are inside the debugger, you type these commands:

- `n` (next): run the current line, and move to the next line without entering functions
- `s` (step): enter the function on the current line
- `c` (continue): run until the next breakpoint or the program ends
- `p variable_name` (print): show the value of a variable
- `l` (list): show the code around the current line
- `w` (where): show the current call stack (where you are)
- `q` (quit): stop the program and leave the debugger
- `h` (help): list all commands

Example session:
```
> calculate_total()
-> total += p
(Pdb) p p
100
(Pdb) p total
0
(Pdb) n
(Pdb) p total
100
(Pdb) c
```

### Setting breakpoints in an IDE: step by step
1. Open your file and click next to the line you want to check. A red dot appears.
2. Click the **Debug** button (not "Run").
3. When the program pauses, use the buttons: **Step Over** (like `n`), **Step Into** (like `s`), **Continue** (like `c`).
4. Hover over a variable, or look at the **Variables** panel, to see its value.

### A real debugging example
Here is a bug. The average is wrong.
```python
def average(marks):
    total = 0
    for m in marks:
        total = m            # BUG: should be total += m
    return total / len(marks)

print(average([80, 90, 70]))   # expected 80.0, actual 23.33...
```
Put a breakpoint inside the loop, and step through. You will see `total` takes the value 80, then 90, then 70, instead of adding up. This shows the bug clearly. The fix is `total += m`.

### Debugging tips
- Use the debugger when a bug is **hard to reproduce** or depends on many variables.
- Use `print()` or logging for quick checks.
- Remove `breakpoint()` before you share or upload code, or it will pause the program for everyone.
