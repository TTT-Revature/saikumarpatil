## 11. Reading Tracebacks and Debugging

### What is a traceback?
When Python hits an error it doesn't handle, it prints a **traceback**: a report showing where the error happened and how the program got there.

```python
def get_average(marks):
    return sum(marks) / len(marks)

def report(class_marks):
    avg = get_average(class_marks)
    print("Average:", avg)

report([])
```
```
Traceback (most recent call last):
  File "main.py", line 8, in <module>
    report([])
  File "main.py", line 5, in report
    avg = get_average(class_marks)
  File "main.py", line 2, in get_average
    return sum(marks) / len(marks)
ZeroDivisionError: division by zero
```

### How to read a traceback: a simple 3-step method
1. **Read the last line first.** It tells you the **error type** (`ZeroDivisionError`) and the **message** (`division by zero`).
2. **Look at the bottom-most `File` line.** That is the exact line where the error happened (`line 2, in get_average`).
3. **Read upward** to see how the program got there. Each line above it is a function call that led to the problem: `report` called `get_average`, which was called from the main code.

Real-life comparison: a **detective's timeline**. The last line is the crime, and the lines above it show the steps that led up to it.

### Common errors students meet
- `NameError`: a variable name is misspelled or not defined yet
- `TypeError`: wrong type used (`"5" + 5`)
- `IndexError`: list index out of range
- `KeyError`: dictionary key not found
- `AttributeError`: object does not have that method (`None.upper()`)
- `IndentationError`: spaces or tabs are wrong (Module 1)

### Debugging strategies (before using tools)
- **Reproduce the error** with the smallest input that causes it.
- **Print or log the variable values** just before the failing line.
- **Read the error message carefully.** It usually tells you exactly what went wrong.
- **Change one thing at a time** and test again.

```python
def get_average(marks):
    print("DEBUG marks =", marks, "count =", len(marks))   # temporary check
    return sum(marks) / len(marks)
```
Remove such temporary prints once you have fixed the bug.
