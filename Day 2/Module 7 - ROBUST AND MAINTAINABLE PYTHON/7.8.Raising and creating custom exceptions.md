## 8. Raising and Creating Custom Exceptions

### Raising your own error with `raise`
Sometimes the program is running without a technical error, but the **data is wrong** for the business rules. Use `raise` to signal that.

```python
def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    print("Age set to", age)

set_age(20)      # Age set to 20
set_age(-5)      # ValueError: Age cannot be negative
```

Real-time example: a **bank counter** refusing a withdrawal. The clerk raises a problem clearly, rather than quietly giving the wrong amount.

### Re-raising an error
Sometimes you want to catch an error, do something (like logging), and then pass it on:
```python
try:
    value = int("abc")
except ValueError:
    print("Logging the problem...")
    raise           # sends the same error upward
```

### Choosing the right built-in exception
Python has many built-in exception types. Use the one that matches the problem:
- `ValueError`: right type, but a wrong value (age = -5)
- `TypeError`: wrong type (adding a string to a number)
- `KeyError`: a dictionary key is missing
- `IndexError`: a list index is out of range
- `FileNotFoundError`: a file does not exist
- `ZeroDivisionError`: dividing by zero

### Creating a custom exception
A custom exception is a new class that inherits from `Exception`. It makes errors specific to your application.

```python
class InsufficientFundsError(Exception):
    """Raised when the balance is too low for a withdrawal."""
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(
            f"Balance {balance} is less than withdrawal {amount}"
        )
    return balance - amount

try:
    new_balance = withdraw(1000, 1500)
except InsufficientFundsError as e:
    print("Transaction failed:", e)
```
```
Transaction failed: Balance 1000 is less than withdrawal 1500
```

### A custom exception with extra information
```python
class ValidationError(Exception):
    def __init__(self, field, message):
        self.field = field
        super().__init__(f"{field}: {message}")

def validate_email(email):
    if "@" not in email:
        raise ValidationError("email", "must contain @")
    return True

try:
    validate_email("asha.gmail.com")
except ValidationError as e:
    print("Invalid", e.field, "→", e)
```
```
Invalid email → email: must contain @
```

> `super().__init__(...)` calls the parent `Exception` class so the message is set properly. You will learn `super()` in Module 8.

### Real-time example: an order system with custom errors
```python
class OutOfStockError(Exception):
    pass

class PaymentError(Exception):
    pass

def place_order(stock, qty, paid, price):
    if qty > stock:
        raise OutOfStockError(f"Only {stock} left in stock")
    if paid < price * qty:
        raise PaymentError("Payment is not enough")
    return "Order placed"

try:
    print(place_order(stock=5, qty=3, paid=500, price=100))
except OutOfStockError as e:
    print("Stock problem:", e)
except PaymentError as e:
    print("Payment problem:", e)
```
