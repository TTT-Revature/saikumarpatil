## 10. Logging and Log Levels 

### Why not just use `print()`?
`print()` works for quick checks, but it has problems in real projects:
- you can't easily turn it off
- it doesn't record the **time** or **where** the message came from
- it doesn't save messages to a file

The `logging` module solves all of these.

Real-life example: a **hospital patient chart**. Notes are written with a date, a time, the name of the nurse and a priority, and they are kept on record. A `print()` is like a sticky note on the desk that disappears.

### Basic setup
```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(levelname)s - %(message)s",
)

logging.info("Application started")
logging.warning("Disk space is getting low")
logging.error("Could not connect to database")
```
```
2026-11-17 10:24:53,123 - INFO - Application started
2026-11-17 10:24:53,124 - WARNING - Disk space is getting low
2026-11-17 10:24:53,125 - ERROR - Could not connect to database
```

### The five log levels
Each level has a number. Only messages at or above the set level are shown.

- `DEBUG` (10): detailed information for developers, for example variable values
- `INFO` (20): normal progress, for example "Order 101 saved"
- `WARNING` (30): something unexpected, but the program still works, for example "Disk almost full"
- `ERROR` (40): a problem stopped one task, for example "Payment failed"
- `CRITICAL` (50): a serious problem, the program may not continue, for example "Database is down"

```python
logging.basicConfig(level=logging.WARNING)

logging.debug("Hidden")        # not shown (below WARNING)
logging.info("Hidden too")     # not shown
logging.warning("Shown")       # shown
logging.error("Shown")         # shown
```

Real-life example: a **traffic signal**. You can set the level to show everything (DEBUG) during testing, and show only emergencies (ERROR and CRITICAL) in production.

### Using a named logger (recommended in real projects)
```python
import logging

logger = logging.getLogger(__name__)

def process_order(order_id):
    logger.info("Processing order %s", order_id)
    logger.debug("Order details loaded")
```

Using `__name__` (from Module 5) records which file the message came from. Also use `%s` style placeholders instead of f-strings inside logging calls, because Python only builds the message if it will actually be shown.

### Logging exceptions with the traceback
```python
import logging

logger = logging.getLogger(__name__)

try:
    result = 10 / 0
except ZeroDivisionError:
    logger.exception("Calculation failed")    # logs the error AND the traceback
```

### Writing logs to a file
```python
import logging

logging.basicConfig(
    filename="app.log",
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s",
    encoding="utf-8",
)

logging.info("This goes into app.log, not the screen")
```

> **Trainer tip:** In real projects, use `logging` for everything you want to remember, and keep `print()` only for user-facing output (like showing a menu). Students should avoid mixing the two for debugging messages.
