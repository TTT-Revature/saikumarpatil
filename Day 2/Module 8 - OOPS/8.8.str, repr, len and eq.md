## 8. `__str__`, `__repr__`, `__len__` and `__eq__`

### Special (magic) methods
Methods with double underscores on both sides, such as `__init__`, are called **special methods** or **dunder methods** (double underscore). Python calls them automatically in certain situations. By defining them, you teach your objects how to behave with built-in features like `print()`, `len()` and `==`.

### `__str__`: a friendly text version (for users)
`__str__` controls what `print()` shows for the object.

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"Student: {self.name} (age {self.age})"

asha = Student("Asha", 21)
print(asha)           # Student: Asha (age 21)
```
Without `__str__`, `print(asha)` shows something unhelpful like `<__main__.Student object at 0x...>`.

### `__repr__`: a precise version (for developers)
`__repr__` gives a detailed, unambiguous text, ideally one that could recreate the object. It is shown in the interactive console and in lists.

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __repr__(self):
        return f"Student(name={self.name!r}, age={self.age})"

asha = Student("Asha", 21)
print(repr(asha))     # Student(name='Asha', age=21)
print([asha])         # [Student(name='Asha', age=21)]
```

> **Rule of thumb:** Always define `__repr__`. If you also define `__str__`, Python uses `__str__` for `print()` and `__repr__` for everything else.

### `__len__`: make `len()` work on your object
```python
class Playlist:
    def __init__(self, songs):
        self.songs = songs

    def __len__(self):
        return len(self.songs)

p = Playlist(["Song A", "Song B", "Song C"])
print(len(p))         # 3
```

### `__eq__`: decide when two objects are "equal"
By default, `==` compares whether two variables point to the **same object** in memory. `__eq__` lets you define equality based on **values**.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

a = Point(2, 3)
b = Point(2, 3)
c = Point(5, 1)

print(a == b)         # True   (same values)
print(a == c)         # False
print(a is b)         # False  (different objects in memory)
```

### Real-time example: a shopping cart
```python
class Cart:
    def __init__(self):
        self.items = []

    def add(self, item, price):
        self.items.append((item, price))

    def __len__(self):
        return len(self.items)

    def __str__(self):
        total = sum(price for _, price in self.items)
        return f"Cart with {len(self)} items, total Rs.{total}"

cart = Cart()
cart.add("Milk", 25)
cart.add("Bread", 40)

print(cart)           # Cart with 2 items, total Rs.65
print(len(cart))      # 2
```

### A quick list of common magic methods
- `__init__`: runs when an object is created
- `__str__`: text for `print()` and `str()`
- `__repr__`: developer-friendly text
- `__len__`: result for `len()`
- `__eq__`: result for `==`
- `__lt__`, `__gt__`: results for `<` and `>` (used by sorting)
