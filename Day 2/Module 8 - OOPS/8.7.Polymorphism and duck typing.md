## 7. Polymorphism and Duck Typing

### What is polymorphism?
**Polymorphism** means "many forms". It is the ability of the **same action** to behave differently depending on the object it is used with.

The OOPS notes give a simple example: `print(5 + 6)`. The number `5` is an integer and `6` is also an integer. Using the `+` operator, they add up to `11`. But `+` also joins strings: `"Sai" + "Kumar"` gives `"SaiKumar"`. The same `+` operator takes **various forms**.

```python
print(5 + 6)              # 11         (adds numbers)
print("Sai" + "Kumar")    # SaiKumar   (joins text)
print([1, 2] + [3])       # [1, 2, 3]  (joins lists)
```

### Polymorphism with methods
Different classes can have a method with the **same name**, and each one behaves its own way. The caller doesn't need to know which class it is.

```python
class Dog:
    def speak(self):
        return "Woof"

class Cat:
    def speak(self):
        return "Meow"

class Cow:
    def speak(self):
        return "Moo"

animals = [Dog(), Cat(), Cow()]

for animal in animals:
    print(animal.speak())
```
```
Woof
Meow
Moo
```
The loop does not care what kind of animal it is. Each object responds in its own way.

### Real-time example: payment methods
```python
class CreditCard:
    def pay(self, amount):
        print(f"Paid {amount} by credit card")

class UPI:
    def pay(self, amount):
        print(f"Paid {amount} using UPI")

class Cash:
    def pay(self, amount):
        print(f"Paid {amount} in cash")

def checkout(method, amount):
    method.pay(amount)          # same code for every payment type

checkout(UPI(), 450)
checkout(Cash(), 120)
```

### Duck typing
Python follows the saying: **"If it walks like a duck and quacks like a duck, it is a duck."**

**Duck typing** means Python does not check an object's class. It only checks whether the object **has the method you need**. If it does, the code works.

```python
class Duck:
    def quack(self):
        print("Quack!")

class Person:
    def quack(self):
        print("I can imitate a duck")

def make_it_quack(thing):
    thing.quack()             # no check on the type, just calls quack()

make_it_quack(Duck())         # Quack!
make_it_quack(Person())       # I can imitate a duck
```

Real-life example: a **power socket** does not care whether you plug in a fan, a lamp or a phone charger. As long as the plug fits and has power, it works.

### What happens if the method is missing?
```python
make_it_quack(5)              # AttributeError: 'int' object has no attribute 'quack'
```

### Checking before calling (when needed)
```python
if hasattr(thing, "quack"):
    thing.quack()
else:
    print("This object cannot quack")
```

> **Trainer tip:** Polymorphism lets you write **one** function that works with many classes. Ask students: "If we add a new payment type tomorrow, do we need to change `checkout()`?" The answer is no, and that is the power of polymorphism.
