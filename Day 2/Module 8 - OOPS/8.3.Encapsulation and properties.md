## 3. Encapsulation and Properties 

### What is encapsulation?
**Encapsulation** is a technique for **hiding the internal details** of a class and exposing **only the information needed for outside interaction**. It keeps data safe, because outside code can't change it in unexpected ways.

Real-life example: an **ATM machine**. You can withdraw cash by pressing buttons, but you can't reach inside and change the balance. The machine's internal workings are hidden, and only the safe buttons are exposed.

Encapsulation can hide both **data** (attributes) and **functions** (methods) that belong to a class.

### Hiding data with underscores
Python uses naming conventions:
- `_name` (single underscore): "internal use, please don't touch from outside" (a convention, not enforced)
- `__name` (double underscore): **name mangling**. Python changes the name, which makes it harder to access by accident.

```python
class Account:
    def __init__(self, balance):
        self.__balance = balance      # hidden (name mangling)

    def get_balance(self):
        return self.__balance

acc = Account(1000)
print(acc.get_balance())      # 1000
# print(acc.__balance)        # AttributeError: no direct access
```

> **Trainer note:** Python does not have strict private variables. A determined programmer can still reach `acc._Account__balance`. The convention is a signal to everyone, and it is considered good practice.

### Controlled access with getters and setters
Instead of letting anyone change a value, provide methods that **check** the value first.

```python
class Account:
    def __init__(self, balance):
        self.__balance = balance

    def get_balance(self):
        return self.__balance

    def set_balance(self, amount):
        if amount < 0:
            print("Balance cannot be negative")
        else:
            self.__balance = amount

acc = Account(1000)
acc.set_balance(-500)         # Balance cannot be negative
print(acc.get_balance())      # 1000  (protected)
```

### Properties: getters and setters that look like attributes
The `@property` decorator (you met decorators in Module 7) lets you write `acc.balance` instead of `acc.get_balance()`, while still running checks behind the scenes.

```python
class Account:
    def __init__(self, balance):
        self.__balance = balance

    @property
    def balance(self):                 # getter
        return self.__balance

    @balance.setter
    def balance(self, amount):         # setter with a check
        if amount < 0:
            raise ValueError("Balance cannot be negative")
        self.__balance = amount

acc = Account(1000)
print(acc.balance)        # 1000        (looks like an attribute)
acc.balance = 1500        # uses the setter
print(acc.balance)        # 1500
acc.balance = -10         # ValueError: Balance cannot be negative
```

### Real-time example: a student's age
```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age          # uses the setter below

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if not 5 <= value <= 100:
            raise ValueError("Age must be between 5 and 100")
        self._age = value

asha = Student("Asha", 21)
print(asha.age)        # 21

try:
    asha.age = 200
except ValueError as e:
    print("Error:", e)  # Error: Age must be between 5 and 100
```

### Abstraction (closely related)
**Abstraction** means showing only the **essential details** of an object and hiding the complicated internal work. It creates a boundary between the application and the client programs.

Real-life example: a **car's steering wheel and pedals**. The driver uses a simple interface. The engine's complicated working is hidden. You don't need to know how the fuel injection works to drive.

```python
class Car:
    def __init__(self):
        self.__engine_on = False

    def __start_engine(self):           # internal detail (hidden)
        self.__engine_on = True
        print("Engine: fuel injected, spark plugs fired")

    def start(self):                    # simple public action
        self.__start_engine()
        print("Car is ready to drive")

my_car = Car()
my_car.start()     # the driver only needs start()
```

> **Encapsulation vs abstraction:** encapsulation is about **hiding the data and methods** inside a class. Abstraction is about **showing only what's needed** to the user. They work together.
