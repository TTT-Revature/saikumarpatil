## 11. Shallow/Deep Copy and Garbage Collection

### Copying objects
As in Module 4, `b = a` does not make a copy. To make an independent copy of an object, use the `copy` module.

```python
import copy

class Team:
    def __init__(self, name, members):
        self.name = name
        self.members = members        # a list inside the object

original = Team("Dev", ["Asha", "Ravi"])
```

### Shallow copy: a new object, but shared inner items
`copy.copy()` creates a new `Team` object, but the `members` list is **still the same list**.

```python
shallow = copy.copy(original)
shallow.name = "QA"                    # changes only the copy's name
shallow.members.append("Meena")        # changes the SHARED list

print(original.name)                   # Dev
print(original.members)                # ['Asha', 'Ravi', 'Meena']  ← changed too!
```

### Deep copy: everything copied
`copy.deepcopy()` copies the object **and all the objects inside it**.

```python
deep = copy.deepcopy(original)
deep.members.append("Kumar")

print(original.members)                # ['Asha', 'Ravi', 'Meena']  (unchanged)
print(deep.members)                    # ['Asha', 'Ravi', 'Meena', 'Kumar']
```

### Summary
- `b = a` → same object, no copy
- `copy.copy(a)` → new outer object, shared inner items (**shallow**)
- `copy.deepcopy(a)` → fully independent (**deep**)

Real-life example: a **photocopy of a document** (shallow copy keeps the attached envelope shared between both copies; deep copy gives you a fresh envelope too).

### Copying your own methods (advanced)
You can control copying by defining `__copy__` or `__deepcopy__`. This is useful when a class holds special resources, but it is beyond the core syllabus.

### Garbage collection: what happens to unused objects
When an object is no longer referenced by any variable, Python **frees its memory automatically**. This process is called **garbage collection**.

Python mainly uses **reference counting**: each object keeps a count of how many names point to it. When the count reaches zero, the memory is released.

```python
import sys

a = Student("Asha")
print(sys.getrefcount(a))     # at least 2 (the name 'a' and the function argument)

b = a
print(sys.getrefcount(a))     # one more reference

del b                          # remove one name
del a                          # no names left → object is freed
```

Real-life example: a **library book**. As long as at least one person holds the book, it stays on the shelf of their hands. When nobody holds it, it goes back on the shelf (is freed).

### Cycles and the `gc` module
Sometimes two objects refer to each other, and their count never reaches zero even when nothing else uses them. Python's `gc` module handles these cycles.

```python
import gc

class Node:
    pass

n1 = Node()
n2 = Node()
n1.partner = n2
n2.partner = n1               # a cycle: they point to each other

del n1, n2
print(gc.collect())           # forces a cleanup; returns the number of objects found
```

> **Trainer note:** Students don't usually need to call `gc.collect()` in real projects. Python cleans up automatically. The important lesson is that **objects are freed when no names refer to them**.

### Using `__del__` (a cleanup hook, use sparingly)
```python
class TempFile:
    def __init__(self, name):
        self.name = name
        print(f"{name} created")

    def __del__(self):
        print(f"{self.name} removed")

t = TempFile("cache.tmp")
del t                          # cache.tmp created → cache.tmp removed
```
Python does not guarantee exactly when `__del__` runs, so for files and connections always prefer `with` (Module 6).
