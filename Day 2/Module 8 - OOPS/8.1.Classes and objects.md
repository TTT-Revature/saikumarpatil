### Big picture first
Until now, our programs were mostly a list of instructions. **Object-Oriented Programming (OOP)** organises code around **objects**: things that have **data** (attributes) and **actions** (methods). This matches how we think about the real world.

There are two common ways to write programs:
- **Procedural programming:** a list of steps, one after another, like a recipe.
- **Object-oriented programming:** you model real-world things (students, bank accounts, cars) as objects, and each object looks after its own data.

The basic idea of OOP in Python is to use **classes** and **objects** to represent real-world concepts and entities.

Real-life example: a **railway booking form**. The blank form is the **class**. Each filled form (Harry's, Tom's, Shuvam's) is an **object**. Every form has the same fields, but each one holds different information.

OOP also helps with the **DRY principle** (*Don't Repeat Yourself*): write the blueprint once, and reuse it for thousands of objects.

## 1. Classes and Objects

### What is a class?
A **class** is a **blueprint** for creating objects. It describes what data an object will hold and what it can do. A class **does not** hold real data by itself.

Real-life example: a **student application form** that is blank. It has fields for name, age and course, but nobody has filled them in yet. That blank form is the class.

### What is an object?
An **object** (also called an **instance**) is a **real thing created from a class**. When a class is defined, a template is defined. When an object is created, that template is used to make a real, filled-in version.

Real-life example: once a student fills in the blank form, it becomes an application form with real details. That filled form is the object.

### Defining a class and creating objects
```python
class Student:
    pass                          # an empty class (just the blueprint)

harry = Student()                 # object 1
tom = Student()                   # object 2

print(type(harry))                # <class '__main__.Student'>
print(harry is tom)               # False (two separate objects)
```

Real-life mapping:
- `Student` → the blank form (class)
- `harry`, `tom` → filled forms (objects)

### Memory is allocated only after an object is created
A class is only a description. Python reserves memory for the data **only when you create an object** from that class. Defining a class uses almost no data memory; each object you create uses its own memory.

### Using the same class for different objects
```python
class Railway:
    pass

harry = Railway()
tom = Railway()
shuvam = Railway()

print(harry, tom, shuvam)       # three different objects, three different addresses
```

> **Trainer tip:** Name classes in **PascalCase** (`StudentRecord`, `BankAccount`). Name objects and variables in **snake_case** (`student_record`, `bank_account`).
