## 3. Context Managers and the `with` Statement

### The problem with `open()` and `close()`
If an error happens between `open()` and `close()`, the `close()` line never runs. The file stays open, which can lock it or lose data.

```python
f = open("data.txt", "r")
content = f.read()
result = int(content)                     # ValueError here if the file is not a number!
f.close()                                 # never reached
```

### The solution: `with`
The `with` statement opens the file, gives it a name, and **closes it automatically** when the block ends, even if an error happens.

```python
with open("data.txt", "r") as f:
    content = f.read()
    print(content)
# the file is closed automatically here
```

Real-life example: a **library book**. The `with` block is like borrowing the book for one task. As soon as you leave the reading room (the block), the book is returned automatically, whether you finished reading or not.

### Working with several files at once
```python
with open("input.txt", "r") as src, open("output.txt", "w") as dst:
    for line in src:
        dst.write(line.upper())
```
Both files are closed when the block ends.

### Checking that the file is closed
```python
f = open("data.txt")
f.close()
print(f.closed)     # True
```
Inside a `with` block, `f.closed` is `False`. After the block, it is `True`.

### Context managers in general
Any object that works with `with` is a **context manager**. The `with` statement does two things:
1. at the start, it calls setup code (for example, opening the file)
2. at the end, it calls cleanup code (for example, closing the file)

You can write your own context manager (this is an advanced topic, so it is good for self-study):
```python
class Timer:
    def __enter__(self):
        print("Start")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("End")

with Timer():
    print("Doing work")
```
```
Start
Doing work
End
```

> **Trainer tip:** Make `with open(...) as f:` the default habit for every file operation. Students should avoid writing `open()` without `with` unless there is a specific reason.
