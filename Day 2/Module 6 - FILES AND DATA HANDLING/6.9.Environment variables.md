## 9. Environment Variables

### What is an environment variable?
An **environment variable** is a setting stored **outside your program**, in the operating system or the terminal. Programs can read them when they run.

Real-life example: a **reception desk** that gives the same instructions to every visitor, such as "the Wi-Fi password is ..." or "the office opens at 9". You don't write those details into every letter. Environment variables work the same way: the settings sit in the environment, and your program looks them up.

Common uses:
- passwords and API keys (secrets)
- database addresses
- switching between "development" and "production" settings
- paths that differ between computers

### Reading environment variables
The `os` module gives you access to them.

```python
import os

print(os.environ.get("USERNAME"))          # Windows user name (or None)
print(os.environ.get("HOME"))              # Linux/Mac home folder
print(os.getenv("PATH"))                   # same idea, using getenv()
```

**`os.environ[...]` vs `os.environ.get(...)`:**
```python
print(os.environ["SOME_MISSING_KEY"])      # KeyError if not set
print(os.environ.get("SOME_MISSING_KEY"))  # None if not set (safer)
print(os.environ.get("SOME_MISSING_KEY", "default"))   # custom fallback
```

### Setting environment variables
In the terminal, before running the program:

Windows (Command Prompt):
```bat
set APP_MODE=development
python app.py
```

Mac/Linux:
```bash
export APP_MODE=development
python app.py
```

Inside Python (lasts only while the program runs):
```python
import os

os.environ["APP_MODE"] = "development"
print(os.environ["APP_MODE"])       # development
```

### Real-time example: database settings
```python
import os

db_host = os.getenv("DB_HOST", "localhost")
db_user = os.getenv("DB_USER", "guest")
db_password = os.getenv("DB_PASSWORD")

if db_password is None:
    print("Warning: DB_PASSWORD is not set")
else:
    print(f"Connecting to {db_host} as {db_user}")
```

### Using a `.env` file (common in real projects)
Developers often keep settings in a file named `.env`:
```
DB_HOST=localhost
DB_USER=asha
DB_PASSWORD=secret123
```
The `python-dotenv` package loads this file into environment variables:
```python
# pip install python-dotenv
from dotenv import load_dotenv
import os

load_dotenv()
print(os.getenv("DB_HOST"))
```

> **Important safety rule:** **Never** write real passwords or API keys directly in your code, and never upload a `.env` file to GitHub. Add `.env` to your `.gitignore` file. Once a secret is in a public repository, treat it as leaked and change it.

### Real-time example: switching behaviour by environment
```python
import os

mode = os.getenv("APP_MODE", "production")

if mode == "development":
    print("Debug messages are ON")
else:
    print("Running in production mode")
```
