## 7. Function Documentation and Type Hints

### Why document functions?
A function written today may be used by a teammate next month, or by you in a year. A **docstring** tells everyone what the function does, what it expects and what it gives back.

### Docstrings
A docstring is a triple-quoted string placed as the **first line inside** the function.

```python
def area_of_rectangle(length, width):
    """
    Calculate the area of a rectangle.

    Parameters:
        length (float): the length of the rectangle
        width (float): the width of the rectangle

    Returns:
        float: the area (length * width)
    """
    return length * width

print(area_of_rectangle.__doc__)
help(area_of_rectangle)
```

### Type hints
Type hints show what **type** each parameter should be and what the function **returns**. Python does not enforce them while running, but editors and tools like `mypy` use them to catch mistakes.

```python
def add(a: int, b: int) -> int:
    return a + b

def greet(name: str) -> None:
    print("Hello", name)
```
- `a: int` means `a` should be an integer
- `-> int` means the function returns an integer
- `-> None` means the function returns nothing

### Docstrings and type hints together
```python
def average(marks: list[int]) -> float:
    """Return the average of a list of marks."""
    return sum(marks) / len(marks)

print(average([80, 90, 70]))    # 80.0
```

> **Tip for students:** Good code has three things: clear names, a short docstring and type hints for the parameters and return value.
