## 12. `__name__` and `if __name__ == '__main__'`

### The problem
Suppose you write `mathutils.py` with some test code at the bottom:
```python
# mathutils.py
def add(a, b):
    return a + b

print("Testing add:", add(2, 3))     # test code
```
When another file **imports** `mathutils`, the test line also runs, which is not wanted.

### The solution
Python sets a special variable called `__name__` for every file:
- If you **run a file directly**, `__name__` is `"__main__"`.
- If the file is **imported** into another file, `__name__` is the **module's name**.

Test it yourself:
```python
# show_name.py
print("__name__ is:", __name__)
```
- Run `python show_name.py` → prints `__name__ is: __main__`
- Import it from another file → prints `__name__ is: show_name`

### The standard pattern
```python
# mathutils.py
def add(a, b):
    return a + b

def main():
    print("Testing add:", add(2, 3))

if __name__ == "__main__":
    main()
```
Now:
- Run `python mathutils.py` → the test runs.
- `import mathutils` in another file → only the functions are loaded, and the test does **not** run.

> **Trainer note:** Write the underscores exactly as `__name__` and `__main__`, with two underscores on each side. `"main"` without underscores will never match.

### Real-time example: a script that is also a library
```python
# converter.py
def celsius_to_fahrenheit(c):
    return c * 9 / 5 + 32

if __name__ == "__main__":
    temp = float(input("Enter temperature in Celsius: "))
    print(f"{temp}°C = {celsius_to_fahrenheit(temp):.1f}°F")
```
- Run it directly → the user is asked for a temperature.
- Import `celsius_to_fahrenheit` in another program → nothing is asked; you just get the function.
