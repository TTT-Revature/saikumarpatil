## 5. Locks

### What is a lock?
A **lock** (also called a mutex) allows only **one thread at a time** to run a protected section of code. Other threads wait at the lock until it is released.

Real-life example: a **single toilet key** hanging at a hostel reception. Only the person holding the key can enter. Everyone else waits until the key comes back.

### Using a lock
```python
import threading

counter = 0
lock = threading.Lock()

def add_many():
    global counter
    for _ in range(1_000_000):
        with lock:                # only one thread inside at a time
            counter += 1

threads = [threading.Thread(target=add_many) for _ in range(2)]
for t in threads:
    t.start()
for t in threads:
    t.join()

print("Expected 2000000, got", counter)    # always 2000000
```

### Why `with lock:` is the best habit
The `with` statement acquires the lock on entry and **always releases it on exit**, even if an error happens inside. Forgetting to release a lock causes a **deadlock**.

Manual version (avoid unless needed):
```python
lock.acquire()
try:
    counter += 1
finally:
    lock.release()
```

### Keep locked sections short
Only protect the code that touches shared data. Slow work (like a network call) inside a lock makes every other thread wait.

```python
# bad: the slow work holds the lock
with lock:
    data = fetch_from_internet()
    shared_list.append(data)

# better: slow work outside, lock only for the shared update
data = fetch_from_internet()
with lock:
    shared_list.append(data)
```

### Deadlock: when threads wait forever
A **deadlock** happens when two threads each hold a lock the other needs.

```mermaid
flowchart LR
    T1[Thread 1 holds Lock A] -->|waits for| L2[Lock B]
    T2[Thread 2 holds Lock B] -->|waits for| L1[Lock A]
    L1 -.-> T1
    L2 -.-> T2
```

Prevention rules:
- Always acquire locks in the **same order** in every thread.
- Keep locked sections short.
- Use `with` so locks are always released.

### RLock: a lock the same thread can acquire again
A standard `Lock` blocks even the thread that already holds it. Use `threading.RLock()` when one locked function calls another locked function.

```python
rlock = threading.RLock()

def outer():
    with rlock:
        inner()

def inner():
    with rlock:       # same thread can enter again
        print("inside inner")

outer()
```

### Real-time example: a shared bank account
```python
import threading

class Account:
    def __init__(self, balance):
        self.balance = balance
        self.lock = threading.Lock()

    def deposit(self, amount):
        with self.lock:
            self.balance += amount

    def withdraw(self, amount):
        with self.lock:
            if self.balance >= amount:
                self.balance -= amount
                return True
            return False

account = Account(1000)

def customer_action():
    account.withdraw(800)

threads = [threading.Thread(target=customer_action) for _ in range(2)]
for t in threads:
    t.start()
for t in threads:
    t.join()

print("Final balance:", account.balance)    # 200, never negative
```
The lock makes the check and the update one protected step, so only one withdrawal of 800 can succeed.
