## 8. Mutable and Immutable Objects

### The core idea
- **Mutable** means the value **can be changed** inside the same object.
- **Immutable** means the value **cannot be changed** inside the same object.

### Real-life example
- **Mutable** is like a **whiteboard**. You can erase and rewrite on the *same* board.
- **Immutable** is like a **printed certificate**. If you need a change, you have to print a *brand new* certificate. The old one stays as it is.

### Which is which?

- **Immutable:** `int`, `float`, `complex`, `bool`, `str`, `tuple`
- **Mutable:** `list`, `set`, `dict`

> All the fundamental data types are immutable.

### Seeing it in code

**Mutable example (list):**
```python
numbers = [1, 2, 3]
print(id(numbers))     # e.g. 140234567

numbers.append(4)
print(numbers)         # [1, 2, 3, 4]
print(id(numbers))     # SAME address, so the same object was modified
```

**Immutable example (string):**
```python
name = "Sai"
# name[0] = "R"        # TypeError: 'str' object does not support item assignment
```

**Immutable example (int), where the address changes:**
```python
a = 10
print(id(a))
a = a + 5
print(id(a))   # DIFFERENT address, because a new object was created
```
We did not *change* `10`. Python created a **new object** `15` and made `a` point to it.

**Tuple vs list:**
```python
my_list = [1, 2, 3]
my_list[0] = 100      # works
print(my_list)        # [100, 2, 3]

my_tuple = (1, 2, 3)
my_tuple[0] = 100     # TypeError: 'tuple' object does not support item assignment
```

### Why does this matter?
- Immutable objects are **safe**. Nobody can accidentally change them (good for fixed data like coordinates or days of the week).
- Mutable objects are **flexible**. You can add, remove and update data (good for shopping carts, to-do lists and so on).
