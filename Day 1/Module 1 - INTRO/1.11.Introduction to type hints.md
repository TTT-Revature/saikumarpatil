## 11. Introduction to Type Hints

### What are type hints?
Python doesn't force you to declare data types. **Type hints** let you *optionally* write down what type you **expect**. They act like a label on a jar saying "Sugar", so everyone knows what should be inside.

> **Important:** Python does **not enforce** type hints while running. They are for **readability, teamwork and tools** (like VS Code or the `mypy` checker), which can warn you about mistakes.

### For variables
```python
name: str = "Asha"
age: int = 21
price: float = 99.5
is_student: bool = True
```

### For functions
```python
def add(a: int, b: int) -> int:
    return a + b

print(add(3, 4))   # 7
```
- `a: int` means *a* should be an integer.
- `-> int` means the function returns an integer.

### Hints for containers
```python
scores: list[int] = [90, 85, 77]
student: dict[str, int] = {"maths": 90, "science": 85}
```

### Python won't stop you from breaking the hint
```python
def greet(name: str) -> str:
    return "Hello " + name

print(greet("Ravi"))    # works
print(greet(123))       # Python raises a TypeError here, because of "Hello " + 123,
                        # NOT because of the hint
```

### Why bother?
- Code is easier to read.
- Editors give better auto-suggestions.
- Bugs are caught earlier.
- It is a very common practice in professional and AI/ML projects.
