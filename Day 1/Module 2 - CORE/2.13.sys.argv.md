## 13. `sys.argv` 

### What is it?
When you run a Python file from the terminal, you can **pass extra information to it** right on the command line. `sys.argv` is a **list** that stores everything typed on the command line.

Real-life example: a restaurant order. You don't walk into the kitchen and ask what's available. You hand the waiter your order (the arguments) at the time of ordering.

### How it works
```python
# file name: greet.py
import sys

print(sys.argv)
```
Run it like this:
```bash
python greet.py Asha 21
```
Output:
```
['greet.py', 'Asha', '21']
```
- `sys.argv[0]` is always the **script name** (`greet.py`)
- `sys.argv[1]` is the first argument (`Asha`)
- `sys.argv[2]` is the second argument (`21`)

### Everything in `sys.argv` is a **string**
Just like `input()`, the values are text. Convert them if you need numbers.

### Real-time example: add two numbers
```python
# file name: add.py
import sys

num1 = int(sys.argv[1])
num2 = int(sys.argv[2])

print("Sum =", num1 + num2)
```
```bash
python add.py 10 20
```
```
Sum = 30
```

### Handling missing arguments
If the user forgets to pass the values, `sys.argv[1]` raises an `IndexError`. Check the length first:

```python
import sys

if len(sys.argv) < 3:
    print("Usage: python add.py <num1> <num2>")
    sys.exit(1)

print("Sum =", int(sys.argv[1]) + int(sys.argv[2]))
```
`sys.exit(1)` stops the program (a non-zero value means "something went wrong").

### Limitations of `sys.argv`
- You have to handle the order of arguments yourself.
- There are no help messages.
- There is no automatic error checking.

That's exactly why we have **`argparse`**, covered next.
