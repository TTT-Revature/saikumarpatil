## 3. List Copying and Mutability

### The big trap: `b = a` does NOT make a copy!

Real-life example: you and your friend share **one Google Doc link**. If your friend edits the document, **you see the change too**, because there is only one document with two names pointing to it.

```python
a = [1, 2, 3]
b = a            # NOT a copy. Both names point to the SAME list

b.append(4)

print(a)         # [1, 2, 3, 4]   ← a changed too!
print(b)         # [1, 2, 3, 4]
print(a is b)    # True           (same object)
print(id(a) == id(b))   # True
```
Both variables are just **two labels on the same object**. Because lists are **mutable**, a change through one name shows up through the other.

### Making a real copy

Real-life example: you **photocopy** the document. Now each person has their own copy.

**Shallow copy** has three equal ways:
```python
a = [1, 2, 3]

b = a.copy()          # method
c = list(a)           # list()
d = a[:]              # full slice
```
```python
b.append(99)
print(a)      # [1, 2, 3]       (unchanged)
print(b)      # [1, 2, 3, 99]
print(a is b) # False           (two different objects)
```

### Why is it called a "shallow" copy?
A **shallow copy** creates a **new outer list**, but the **inner objects are still shared** (not copied). This only matters when the list contains **mutable items** like another list.

```python
a = [1, 2, [10, 20]]
b = a.copy()

b[2].append(30)     # change the INNER list through b

print(a)     # [1, 2, [10, 20, 30]]   ← a changed too!
print(b)     # [1, 2, [10, 20, 30]]
```
The outer lists are different, but the inner list `[10, 20, 30]` is **the same object** in both.

### Deep copy: a fully independent copy
A **deep copy** copies **everything, including the inner objects**. Use the `copy` module.

```python
import copy

a = [1, 2, [10, 20]]
b = copy.deepcopy(a)

b[2].append(30)

print(a)     # [1, 2, [10, 20]]       (unchanged)
print(b)     # [1, 2, [10, 20, 30]]
```

### Summary of the three situations
- **`b = a`** → same object. No copy at all.
- **`b = a.copy()`** → new outer list; inner objects are still shared (**shallow**).
- **`b = copy.deepcopy(a)`** → everything is copied (**deep**).

### Mutability: why this matters
- **Immutable** objects (int, str, tuple) can't be changed, so sharing them is safe.
- **Mutable** objects (list, set, dict) can be changed, so sharing them can cause **surprises**.

```python
x = 10
y = x
y = y + 5
print(x, y)      # 10 15   (x is safe, because ints can't be modified)
```

### Mutable default values and functions
Passing a list to a function **lets the function change your original list**:
```python
def add_item(items):
    items.append("new")

my_list = [1, 2]
add_item(my_list)
print(my_list)       # [1, 2, 'new']
```
If you don't want this, pass a copy: `add_item(my_list.copy())`.

### A common bug: duplicating a nested list
```python
grid = [[0] * 3] * 3       # looks right but is WRONG
grid[0][0] = 1
print(grid)                # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]  ← all rows changed!

grid = [[0] * 3 for _ in range(3)]    # correct way
grid[0][0] = 1
print(grid)                # [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
```
The first version repeats **the same inner list** three times.
